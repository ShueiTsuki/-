# 和原版对拍

同一批咒术，原版咒法学（HexMod 0.11.4，Fabric 1.20.1）和移植版各跑一遍，逐步比对。原版就是标准答案。

## 比什么

每个用例是「初始栈 + 一串 iota」。照原版法杖的方式一个一个执行：每步新建施法环境，施法镜像接着用，栈清空就换新镜像。每一步比：

- 结果类型（执行了 / 转义了 / 出错了 / 不是图案……）
- 栈（数按相对误差 1e-9 比）
- 事故（类名；移植版改了名、意思一样的在对拍程序里登记别名）
- 扣了多少媒质、用了多少操作数、括号层数、转义状态、栈是否清空、渡鸦之思

消息文字不比：原版服务器只有英文，移植版是中文。随机数只比「是个 0 ~ 1 之间的数」。

## 文件

| 路径 | 作用 | 进仓库 |
|---|---|---|
| `mc/` | 测试模组（Java），放进原版服务器，执行用例、导出结果 | 是 |
| `original.py` | 编译测试模组、起没有界面的 MC 服务器跑原版 | 是 |
| `gen_cases.py` | 生成用例：图案笔顺一律取自原版运行时导出的注册表 | 是 |
| `golden/registry.json` | 原版运行时的图案注册表（id、起始方向、笔顺、是不是本世界图案、实现类、是不是法术） | 是 |
| `golden/basic.json.gz` | 原版跑 `cases/basic.json` 的结果，即标准答案 | 是 |
| `port/` | 移植版这一侧：直接编译模组的 `Core/`，跑同样的用例并比对；`SceneWorld.cs` 是照原版场景布置的世界 | 是 |
| `cases/`、`out/` | 生成的用例、比对报告 | 否 |

`_tools/run_all.ps1` 里的「和原版对拍」一步只跑移植版这一侧，拿入库的标准答案比，不需要 MC。

## 原版那边的运行目录

MC 本体、依赖、世界存档都不进仓库，放在 `D:/DeepSeekHarness/oracle_run`，可以用环境变量 `HEXORACLE_RUN` 改位置。里面要有：

- `minecraft-1.20.1.jar`：MC 1.20.1 本体。客户端 jar 也行，它里面带着专用服务器的入口；
- `classpath.txt`：Fabric 加载器和 MC 的库，分号分隔；
- `mods/`：咒法学 0.11.4 和它的依赖，包括 fabric-api、fabric-language-kotlin、cardinal-components、paucal、cloth-config、patchouli、inline；
- `eula.txt`（`eula=true`）和 `server.properties`：平坦世界、离线模式、关掉生物生成。

第一次起服务器时，Fabric 会把 MC 本体转成中间名，放在 `.fabric/remappedJars/` 里，测试模组就拿它来编译。

## 用例改了以后

```
python tests/oracle/gen_cases.py
python tests/oracle/original.py build
python tests/oracle/original.py run tests/oracle/cases/basic.json tests/oracle/golden/basic.json.gz
```

改了生成器却没重跑原版，对拍会报「原版没有结果」并判红。

## 测试场景

移植版的世界是 z = 0 的平面，所以原版那边的场景也全放在这个平面上（`mc/src/hexoracle/Scene.java`），移植版这边照样布置（`port/SceneWorld.cs`）：

- 平坦世界：基岩 y=-64，泥土 -63、-62，草方块 -61，地面在 y=-60；石头 (2, -60, 0)
- 施法者：脚底 (0.5, -60, 0)，面朝 +x；原版那边是假玩家，**不在世界的实体列表里**，区域查询和射线碰不到它
- 猪 `pig`：(3.5, -60, 0)，不动、不受伤；掉落物 `item`：(-2.5, -60, 0)，3 个紫水晶粉

用例里用 `{"t":"entity","ref":"pig"}` 这样的名字引用它们。几件要注意的事：

- 每个用例开始前清掉场景以外的实体：所有用例在服务器的同一刻里跑完、世界不走刻，原版「位置太远」之类的事故会把施法者手上的东西扔出去，
  空手也生成一个空的掉落物，真实游戏里下一刻就清掉了，这里会越积越多；
- `summon` 会把整数坐标挪到格子中心（0 变成 0.5），所以场景坐标写 `0.0`；
- MC 实体的身高、眼高是单精度（猪身高 0.9f = 0.8999999761581421），`SceneWorld` 照存单精度；
- 场景世界里的规则（施法范围、按位置找实体、区域找实体）是照原版写在测试里的 —— 移植版这些规则在泰拉那一侧，离线测不到，
  这里测的是核心里图案的逻辑（先查什么、报哪种事故、返回什么、射线和扫掠的几何）。

## 已知差异与比不了的

- 射线打中方块：原版给方块中心，方块在 z = 0 那一格，中心 z = 0.5；移植版的世界是 z = 0 的平面（AUDIT「3D → 2D 适配」A9），中心取 z = 0。对拍时把原版的 0.5 换成 0 再比。
- 移植版改了名、意思一样的事故登记成别名：手持物品不对 = 原版的副手物品不对；超出影响范围 = 原版的「位置不对（太远）」。
- 把施法者本人写进渡鸦之思：渡鸦之思存的是数据，读回来要按 UUID 到世界里找人，原版那边的假玩家不在世界里，找不回来 —— 这几个用例不生成。

## 范围

- **已经比**：
  - 所有非卓越的图案，配几十种初始栈：类型对的、错的、参数不够的、NaN、正负无穷、很深的嵌套、很长的列表；
  - 数字和簿记员的特殊图案；
  - 多步程序：内省、反思、赫尔墨斯、伊里斯、托特、卡戎、跳转 iota、括号、渡鸦之思、操作数上限、栈超过 1024；
  - 测试场景里：实体、坐标、射线、区域查询、方块比较；
  - 法术：只在那组「坐标都离施法者 60 格开外、没有实体」的初始栈上跑，参数过不了检查，原版那边的场景不会被改。
- **还没比**：
  - 法术真正生效以后改了世界的结果（要给每个用例重置场景、比改动后的世界）；
  - 卓越法术（两边的本世界笔顺不一样，要各自换算）。
