# HexParse（附属）

上游：[YukkuriC/HexParseMod](https://github.com/YukkuriC/HexParseMod) 1.20.1-1.11.2，MIT。

**是什么**：在聊天栏用 `/hexParse <代码>` 把一段代码写进手上的核心 / 结念绳 / 法术书（当前页），反过来也能把里面的咒术读成代码；另有 8 个图案、注释 iota、宏与别名。完整用法见咒法学之书「咒法学 → HexParse指令」。

**开关**：模组配置「咒法学 · 附属兼容（服务端）」-> HexParse。默认关；关着 = 没装。联机由开服的人决定，改了要重载模组。开关下面的「HexParse 设置」是上游的 10 项配置，房主随时能改。

**状态**：P1 完成（纯逻辑 + 游戏侧 + 书页），「嵌套列表 / 括号彩色显示」也已做（本体的 iota 显示按原版重做以后接上的，见 AUDIT_VS_ORIGINAL.md「iota 的显示」）；离线用例在 `tests/vmtest/Addons/HexParseTests.cs`。功能与文件的对照见 `addon.json` / 仓库根目录的 `ADDONS.generated.md`。

## 怎么用（最常用的）

- `/hexParse "add, sub"`：解析代码写进手上的核心。带空格、逗号的代码要用双引号括起来（同上游）。
- `/hexParse read`：把手上核心里的咒术读成代码，结果写进剪贴板。
- `/hexParse clipboard`：把剪贴板里的代码写进手上的核心。
- 「另一只手」= 快捷栏里手上那格右边一格：核心放在法杖右边，拿着法杖也能读写。

## 与上游的偏差

| 上游 | 泰拉侧 | 原因 |
|---|---|---|
| 实体写成 `entity_<UUID>` | `entity_player_编号` / `entity_npc_编号` / `entity_item_编号` / `entity_projectile_编号` / `entity_itemframe_编号`（物品框） | 泰拉的实体没有 UUID；编号跨存档不稳定（上游的 UUID 在别的世界也找不到，行为一样变成 null） |
| 读出的代码点一下复制 | 直接写进剪贴板，并提示「已复制到剪贴板」 | 泰拉聊天不能点击复制 |
| 彩色显示是客户端设置，各人看各人的 | 是「HexParse 设置」里的一项（房主定）；聊天栏里揭示、事故消息的颜色在生成消息的那一端定下 | 移植版的 HexParse 设置统一放在服务端配置里；消息是带颜色标记的文字，发出去以后不再重算 |
| 重命名 = 改物品的名字 | 物品上存一个自定义名，显示在名字那一行（存档 / 联机都带着） | 泰拉的物品没有改名功能 |
| `nbt_…` = MC 的 NBT 编码 | 本模组 iota 信封的编码（外层 zlib + Base64 + 同样的字符替换） | 泰拉没有 NBT；MC 导出的 `nbt_` 串读不出来，反之亦然 |
| 解析在服务端做，宏进服时发给服务端 | 解析在本人客户端做，宏只存在客户端 | 泰拉的物品、剪贴板都归客户端；只有改世界表（学大法术、unlock_great、conflict set）发给服务端 |
| `conflict` / `unlock_great` 要 OP 权限 | 单人游戏或房主 | 泰拉没有权限系统（和 /hexcasting 指令同一个规矩） |
| `.hexpattern` 按客户端语言的图案名反查，还能拿服务端的英文名表 | 按官方中文名反查（本模组界面是中文），不做英文名表同步 | 上游这项本来就是实验性质；syncDisplayToClient 只服务于它 |
| 编译术 / 注释转换：装了 MoreIotas 才有效 | 一直是空动作 | 泰拉侧没有 MoreIotas（字符串 iota），和上游没装它时一样 |
| Hexcellular 的 `property` 读写、其他附属的插件解析 | 不做 | 那些附属没有移植 |

照搬的「怪行为」（上游如此，不当 bug 改）：写入不看密封、结念绳也能覆盖；`mask_` 的第一个字符由起笔那一段表示；分词正则不锚定开头（开头认不出的字符直接跳过）。
